# Dispatcher Decision Rules

This is the inventory of the rules that decide the dispatcher's next step for an issue or PR (issue #555, Epic #519). `src/headless_pr_workflow/dispatcher/rules.py` records the same rules as data, and `tests/test_dispatcher_rules_registry.py` fails when the two name different rules, when a listed marker is no longer in its file, or when a row and the registry disagree on a marker or on a suspected disagreement.

The duplicate-rule guard (#570) reads the registry; the parity baseline (#571) proves or disproves each suspected disagreement; #556, #557 and Feature #526 move each rule into its owner. This inventory changes no decision. `src/headless_pr_workflow/next_action.py` is advisory and the dispatcher does not call it, so it is not listed. The board status display (`dispatcher/status.py`) appears only where it reads the same facts as a rule.

## Decision rules

How to read a row:

- **Implementations** names each file that implements the rule and, after the colon, the marker for each implementation: a function, variable, constant or jq name that appears literally in that file. The owner is the file the rule is meant to live in; every other file in the row is a known duplicate location, the allowlist that the guard (#570) shrinks.
- **Entry points**: `poll` is `scripts/dispatcher-poll.sh`; `invoke` is the new-work path of `scripts/dispatcher-invoke.sh` (Steps 1 to 6, the `/implement` hand-off and `next_new_work`); `resume` is `run_resume_pass` and its steps; `codex-worker` is `scripts/codex-worker.sh`, which runs `codex_worker.py`.
- **Tests** are the files under `tests/` that exercise the rule.
- **Copies** is `Single copy` when only one file implements the rule, `Agree` when the copies are believed to match, and **Suspected:** with the reason when they are suspected to disagree.

Source: `main` at `be4afc3`.
